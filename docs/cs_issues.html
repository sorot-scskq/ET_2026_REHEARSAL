1. つまみ（走行体に置くテキスト。再ビルド不要）

走行体はリポジトリの checkout なので、ソースの既定値を書き換えても git pull で戻る。そこで ./sorot_spike/<名前>.txt の1行目に 1 か 0 を置いて上書きする。ファイルが無ければソースの既定で動く。 置いたらコミットして残すこと（管理外だったときは作り直しで消え、経路が 40cm 伸びた）。

つまみソースの既定何のためのつまみか
turn_drift.txt1（置いてあるのは 0）旋回中に車体が並進するぶんを、手前の直進の SCD から先に差し引く補正
follow_plan.txt1走りながら自己位置を見て、先の行の SCD/SCR を書き直すか（開ループをやめる）
heading_hold.txt1直進を、ジャイロの向きを保つ直進（FUNCNO 19）で走るか、エンコーダ補正の直進（FUNCNO 5）で走るか
heading_camera.txt1旋回直後の直進に、床のコードで向きを測る SCRIPT を差し込むか
heading_fix.txt（廃止予定）0測った向きを、走らせ方の目標だけでなく自己位置にも打ち直すか。もう使っていない（10/31 の develop は打ち直しを止めてファイルも無くした。#76・#77）
position_fix.txt0床のコードから出した位置のずれで自己位置を打ち直すか
gate_check.txt1ゲートをカメラで見て「通れる／当たる」を記録するか（走りは変えない）
gate_steer.txt0ゲートの観測を走りへ返し、中心へ寄せるか
cycle_overrun_ms.txt50周期が何 ms を超えたら記録するか（0 で止める）

各つまみの要点

つまみ要点注意
turn_drift「旋回で後ろへ下がる」ぶんを先に余分に走る理屈。下がらない今の機体では、足したぶんがそのまま行き過ぎになる9/25 に 0 にした。1 のとき直進1本ごとに 2〜3cm、18本で 40cm 超。戻すのは TURN_DRIFT_MM を測り直したときだけ。効いているかは grep "旋回中の並進" ev3_python.log（「相殺: しない」が正しい）
follow_plan9/21 の実機で終点の開きが 84/90/108mm → 23/63mm0 にしても止まりはしない。安定版は 0
heading_holdFUNCNO 5 は滑りで向きがずれても気づかないジャイロは直進するだけで ±5°/80cm の実在しない回転を積む（#54）。保とうとして実際に曲がり、記録では真っ直ぐに見える。それを外から直すのが heading_camera
heading_camera床のコードは動かないので、旋回直後にカメラが格子に対する向きを測って目標を直す直すのは目標だけ。自己位置は heading_fix
heading_fix向きは「操舵の目標」と「x/y を積む方位」の2か所にある。0 だと走りは直っても自己位置が古い向きのまま積み続ける床のコードの一辺のログは 1 のときだけ出る。符号が逆の疑いがある（#76）。このつまみはもう使っていない（廃止予定）
position_fix床のコードに当てて x/y を打ち直す自己位置が半マス以上ずれていると隣のコードに当てる（違う場所へ飛ぶ）。実機では未確認
gate_check自己位置の記録は実際の曲がりを隠す。ゲートは動かない外の基準止めも曲げもしない
gate_steer向きを少し振って中心へ寄せる。振ったまま着くと 1° あたり 3.8mm 狭くなるので、遠くで振って 350mm 以内で正面に戻す直せるのは約 49mm まで（片側の余裕 47.5mm）。俯角が狂うとゲートを測れない。安定版は 0（寄せない）
cycle_overrun_msasp は 0.5〜1.25 秒固まることがあり、その間モータは最後の指令のまま走るしきい値を超えたら、どのタスクのどの区間かを1行残す

2. 実測・公式の値（変えない）

カメラが見た画素を床の mm に戻す物差し。1つ違うと距離も間隔も倍率でずれ、原因も見分けがつかない。実測がある量から固定し、残った1つ（俯角）だけを動かす。

量値何のための値か出どころ
色が始まる高さ45.0mm柱の色は床から 45mm 上で始まる。床と思うと間隔が 1.28倍に膨らむ実測
床 → レンズ205.0mm床までの距離はこの高さに比例する実測
足元のすき間230.0mm走行体が通る幅。車体 135mm なので片側の余裕は 47.5mm実測
継手の外径24mmすき間と芯々の差メーカー公式
柱の芯々254.0mmカメラの物差し（検算用）。通れる幅ではない230＋24
車体の前から車軸80.0mm距離の基準点（回っても動かない点）実測
車輪の半径27.5mm回転を距離に直す係数。自己位置のすべてがここに乗る実測
トレッド112.0mm旋回角度の換算実測

柱の芯々は 258 → 248 → 258 → 254 と4回動いた。数字を焼き込まない。

4. ゲートの観測を信じる条件（Python）

カメラは斜めから見たり枚数が足りなかったりすると、平気で嘘の値を出す。嘘の値で寄せると当たる側へ寄せるので、「測れたが信じない」を作ってある。締めすぎると、当たっていた観測まで捨てる。

定数開発版安定版意味
TRUST_APPROACH_DEG10.0°15.0°これより斜めなら観測を信じない
MIN_VERDICT_FRAMES3無し判定に要る枚数。足りなければ「信用できません」と書く
MAX_APPROACH_DEG8.0°20.0°これより斜めなら寄せない
SQUARE_UP_APPROACH_DEG25.0°―近くでは緩める
SQUARE_UP_MM350.0mm―正面へ戻す段に入る距離
MAX_SPAN_ERROR_MM50.0mm―間隔が 254±50 を外れたら測りを疑う

9/25 に一度 5° へ締めたが、当たっていた観測（7.1°・4枚）を捨てて外れた観測（4.4°・2枚）を残したので 10° に戻した。効いていたのは角度より枚数。

走りそのものを作っている値。速度と電池で変わる値が混ざっているので、速度を変えたら校正が無効になる。

定数値何のためか

7. 罠

  • 同じ名前で符号が逆の定数がある。 heading_reader.CAMERA_TO_AXLE_FORWARD_MM = -20、gate_finder は +20。どちらを import したかで 40mm ずれるが、一定のずれなので気づきにくい。
