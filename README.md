### 1. つまみ（走行体に置くテキスト。再ビルド不要）

走行体はリポジトリの checkout なので、ソースの既定値を書き換えても `git pull` で戻る。そこで `./sorot_spike/<名前>.txt` の1行目に `1` か `0` を置いて上書きする。**ファイルが無ければソースの既定で動く。** 置いたらコミットして残すこと（管理外だったときは作り直しで消え、経路が 40cm 伸びた）。

| つまみ | ソースの既定 | 何のためのつまみか |
| --- | --- | --- |
| **`turn_drift.txt`** | 1（置いてあるのは **0**） | 旋回中に車体が並進するぶんを、手前の直進の `SCD` から先に差し引く補正 |
| `follow_plan.txt` | 1 | 走りながら自己位置を見て、先の行の `SCD`/`SCR` を書き直すか（開ループをやめる） |
| `heading_hold.txt` | 1 | 直進を、ジャイロの向きを保つ直進（FUNCNO 19）で走るか、エンコーダ補正の直進（FUNCNO 5）で走るか |
| `heading_camera.txt` | 1 | 旋回直後の直進に、床のコードで向きを測る `SCRIPT` を差し込むか |
| `heading_fix.txt`（**廃止予定**） | 0 | 測った向きを、走らせ方の目標だけでなく**自己位置にも**打ち直すか。**もう使っていない**（10/31 の develop は打ち直しを止めてファイルも無くした。#76・#77） |
| `position_fix.txt` | 0 | 床のコードから出した**位置**のずれで自己位置を打ち直すか |
| `gate_check.txt` | 1 | ゲートをカメラで見て「通れる／当たる」を記録するか（走りは変えない） |
| `gate_steer.txt` | 0 | ゲートの観測を走りへ返し、中心へ寄せるか |
| `cycle_overrun_ms.txt` | 50 | 周期が何 ms を超えたら記録するか（0 で止める） |

**各つまみの要点**

| つまみ | 要点 | 注意 |
| --- | --- | --- |
| `turn_drift` | 「旋回で後ろへ下がる」ぶんを先に余分に走る理屈。**下がらない今の機体では、足したぶんがそのまま行き過ぎになる** | 9/25 に 0 にした。1 のとき直進1本ごとに 2〜3cm、18本で 40cm 超。戻すのは `TURN_DRIFT_MM` を測り直したときだけ。効いているかは `grep "旋回中の並進" ev3_python.log`（「相殺: しない」が正しい） |
| `follow_plan` | 9/21 の実機で終点の開きが 84/90/108mm → 23/63mm | 0 にしても止まりはしない。**安定版は 0** |
| `heading_hold` | FUNCNO 5 は滑りで向きがずれても気づかない | ジャイロは直進するだけで ±5°/80cm の**実在しない回転**を積む（#54）。保とうとして実際に曲がり、記録では真っ直ぐに見える。それを外から直すのが `heading_camera` |
| `heading_camera` | 床のコードは動かないので、旋回直後にカメラが格子に対する向きを測って目標を直す | 直すのは目標だけ。自己位置は `heading_fix` |
| `heading_fix` | 向きは「操舵の目標」と「x/y を積む方位」の2か所にある。0 だと走りは直っても自己位置が古い向きのまま積み続ける | 床のコードの一辺のログは 1 のときだけ出る。**符号が逆の疑いがある（#76）**。**このつまみはもう使っていない（廃止予定）** |
| `position_fix` | 床のコードに当てて x/y を打ち直す | **自己位置が半マス以上ずれていると隣のコードに当てる**（違う場所へ飛ぶ）。実機では未確認 |
| `gate_check` | 自己位置の記録は実際の曲がりを隠す。ゲートは動かない外の基準 | 止めも曲げもしない |
| `gate_steer` | 向きを少し振って中心へ寄せる。振ったまま着くと 1° あたり 3.8mm 狭くなるので、遠くで振って 350mm 以内で正面に戻す | **直せるのは約 49mm まで**（片側の余裕 47.5mm）。俯角が狂うとゲートを測れない。**安定版は 0（寄せない）** |
| `cycle_overrun_ms` | asp は 0.5〜1.25 秒固まることがあり、その間モータは最後の指令のまま走る | しきい値を超えたら、どのタスクのどの区間かを1行残す |

### 2. 実測・公式の値（**変えない**）

カメラが見た画素を床の mm に戻す物差し。1つ違うと距離も間隔も倍率でずれ、原因も見分けがつかない。**実測がある量から固定し、残った1つ（俯角）だけを動かす。**

| 量 | 値 | 何のための値か | 出どころ |
| --- | --- | --- | --- |
| 色が始まる高さ | 45.0mm | 柱の色は床から 45mm 上で始まる。床と思うと間隔が 1.28倍に膨らむ | 実測 |
| 床 → レンズ | 205.0mm | 床までの距離はこの高さに比例する | 実測 |
| 足元のすき間 | 230.0mm | **走行体が通る幅**。車体 135mm なので片側の余裕は **47.5mm** | 実測 |
| 継手の外径 | 24mm | すき間と芯々の差 | メーカー公式 |
| 柱の芯々 | 254.0mm | カメラの物差し（検算用）。通れる幅ではない | 230＋24 |
| 車体の前から車軸 | 80.0mm | 距離の基準点（回っても動かない点） | 実測 |
| 車輪の半径 | 27.5mm | 回転を距離に直す係数。自己位置のすべてがここに乗る | 実測 |
| トレッド | 112.0mm | 旋回角度の換算 | 実測 |

柱の芯々は 258 → 248 → 258 → 254 と4回動いた。数字を焼き込まない。

### 3. 機体ごとのカメラ校正（`RoughSpot/Python/2026/camera_calib/<機体>/`）

**安定版にはこの校正が無く、俯角は 21.0° 固定。** 開発版には有る。`fx`/`cy` はチェスボードから出る固い値で、**俯角だけは写真に写らない**ので人が入れる。

| 機体 | 俯角 | fx | cy |
| --- | --- | --- | --- |
| scsk2 | 18.2° | 1317.5 | 320.3 |
| scsk3 | 22.0° | 1271.9 | 365.5 |
| 読めないとき | 21.0° | 1258.8 | 359.5 |

- 俯角は定数ではない。柱に当たるたびに動く（1日で約 1°）。信用できるのは 400〜900mm の帯だけ（#60）。
- 校正が読めたかは起動ログで確かめる。**ファイルに 18.2 と書いてあっても、読めなければ 21.0 で走る。**

### 4. ゲートの観測を信じる条件（Python）

カメラは斜めから見たり枚数が足りなかったりすると、平気で嘘の値を出す。嘘の値で寄せると当たる側へ寄せるので、「測れたが信じない」を作ってある。締めすぎると、当たっていた観測まで捨てる。

| 定数 | 開発版 | 安定版 | 意味 |
| --- | --- | --- | --- |
| `TRUST_APPROACH_DEG` | 10.0° | **15.0°** | これより斜めなら観測を信じない |
| `MIN_VERDICT_FRAMES` | 3 | **無し** | 判定に要る枚数。足りなければ「信用できません」と書く |
| `MAX_APPROACH_DEG` | 8.0° | **20.0°** | これより斜めなら寄せない |
| `SQUARE_UP_APPROACH_DEG` | 25.0° | ― | 近くでは緩める |
| `SQUARE_UP_MM` | 350.0mm | ― | 正面へ戻す段に入る距離 |
| `MAX_SPAN_ERROR_MM` | 50.0mm | ― | 間隔が 254±50 を外れたら測りを疑う |

9/25 に一度 5° へ締めたが、当たっていた観測（7.1°・4枚）を捨てて外れた観測（4.4°・2枚）を残したので 10° に戻した。効いていたのは角度より**枚数**。

### 5. 打ち直しの上限（Python）

間違えると違う場所へ飛ぶので上限がある。**超えたら打ち直さず見送る。**

| 定数 | 開発版 | 安定版 | 意味 |
| --- | --- | --- | --- |
| `MAX_CORRECTION_DEG` | **15.0°** | **5.0°** | 向きの打ち直しの上限（入口 29/2。#59・#62） |
| `MIN_MARKERS` | 4 | ― | 目印がこれ未満なら位置を出さない |
| `MAX_OFFSET_MM` | 約 82mm | ― | 格子の 1/3。超えたら取り違えとみなす |
| `MAX_DEVIATION_DEG` | 6.0° | ― | 同上（向き） |
| `TURN_DRIFT_MM` | -25.9 / 4.6 / -29.7 / 1.1 | 同じ | 旋回中の並進の見込み。**いまの機体には 16〜20mm 大きい** |

### 6. C++ の校正定数（**走行体で `make` が要る**。版による差なし）

走りそのものを作っている値。速度と電池で変わる値が混ざっているので、速度を変えたら校正が無効になる。

| 定数 | 値 | 何のためか |
| --- | --- | --- |
| `STOP_LEAD_TIME` | 0.073s | 止まる指令から止まるまでの空走を見込んで先に止める。速度に比例し、冷間と温間で 11% 違う |
| `NXT_WHEEL_RADIUS` | 27.5mm | 回転 → 距離 |
| `NXT_WHEEL_INTERVAL` | 112.0mm | 左右差 → 旋回角度 |
| `NXT_WHEEL_TURN_SLIP` | 1.031 | 旋回の横滑り。各輪 PWM 40 で 1.031、100 で 1.333。旋回を速くすると無効 |
| `KP_REFERENCE_FWD` | 40 | ライントレースの P を速度で割り戻す基準 |
| `HEADING_CORRECT_MAX_DEG` / `COORD_CORRECT_MAX_DEG` | 10.0° | 向きの補正・自己位置の打ち直しの C++ 側の上限（#62） |

### 7. 罠

- **同じ名前で符号が逆の定数がある。** `heading_reader.CAMERA_TO_AXLE_FORWARD_MM = -20`、`gate_finder` は `+20`。どちらを import したかで 40mm ずれるが、一定のずれなので気づきにくい。
- **経路の `Comment` の距離と `SCD` は別の量。** `Comment` は PC が書いた補正前、`SCD` は `turn_drift` で相殺した後。食い違っていても不具合ではない。
- **電池を替えたら測り直す量がある**（`STOP_LEAD_TIME`・`TURN_DRIFT_MM`）。
